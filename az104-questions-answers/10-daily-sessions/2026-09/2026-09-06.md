## Weak Areas

### 1. Managed Identity vs SAS

Q11 exposed an important distinction:

SAS provides delegated, time-limited access.

Managed Identity is the preferred identity-based approach for Azure workloads when supported and avoids storing application credentials.

### 2. Managed Identity vs Key Vault

Q16 reinforced that Key Vault stores secrets, while Managed Identity can eliminate the need to store a storage key or SAS token.

### 3. SAS Permissions vs RBAC Roles

Q18 reinforced that SAS permissions are not Azure RBAC roles.

SAS:

- Read
- Write
- Delete
- Scope
- Expiration

RBAC:

- Storage Blob Data Reader
- Storage Blob Data Contributor
- Role assignment
- Scope

## Troubleshooting Learning

Q20 reinforced the distinction between authentication and authorization.

Authentication:

Managed Identity
  |
  +-- Microsoft Entra ID
  |
  +-- Identity established

Authorization:

Azure RBAC
  |
  +-- Storage Blob Data Reader
  |
  +-- Storage Blob Data Contributor

A successful authentication does not guarantee permission to perform the requested operation.

For:

403 AuthorizationPermissionMismatch

check:

1. Identity
2. Authentication
3. Data-plane role
4. RBAC scope
5. Requested operation
6. Whether the role permits that operation
