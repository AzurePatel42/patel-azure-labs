## Key Corrections

### 1. Windows VM Remote Administration

Windows Server normally uses RDP over TCP 3389.

Linux normally uses SSH over TCP 22.

Remote access also requires the network path, NSG rules, source restrictions, and guest OS authentication to be correct.

Do not expose RDP broadly to the public internet.

### 2. Azure RBAC vs Guest OS Permissions

Azure resource permissions and guest OS permissions are separate layers.

Azure Resource Management
    ->
Azure RBAC

Guest OS Login
    ->
Virtual Machine User Login
    ->
Virtual Machine Administrator Login

Having an Azure resource-management role does not automatically make a user a Windows administrator inside the VM.

### 3. Availability Sets vs Availability Zones

Availability Sets distribute VMs across fault domains and update domains.

Availability Zones place workloads in physically separate locations within an Azure region.

Traffic surge is a scaling problem, not an availability-set problem.

### 4. Storage Redundancy vs VM Availability

Storage redundancy such as ZRS is not the same as VM compute availability.

For compute availability, use:

- Availability Sets
- Availability Zones
- Multiple healthy VM instances

### 5. Load Balancer vs VMSS

Load Balancer distributes traffic to healthy backend instances.

VMSS manages the VM instances and can provide autoscaling and instance lifecycle management.

The Load Balancer does not independently remove and recreate VM instances.

### 6. Application Health vs VM Health

A VM can be running while the application inside it is unhealthy.

Health probes determine whether traffic should be sent to an instance.

VMSS health and repair capabilities can be used to manage unhealthy instances depending on configuration.

### 7. Temporary Disk vs Persistent Data

Temporary disk is intended for temporary and non-persistent data.

Important application or database data should use persistent Azure managed disks with an appropriate performance tier.

### 8. Key Vault + Managed Identity

Application secrets should not be placed directly into source code or ordinary configuration files.

Use:

Application
    ->
Managed Identity
    ->
Microsoft Entra ID
    ->
Azure RBAC
    ->
Key Vault

Key Vault stores the secrets.

Managed Identity provides the application's identity.

### 9. VM Performance Troubleshooting

Do not assume CPU is the bottleneck.

Investigate:

- CPU utilization
- Memory
- Disk I/O
- Disk latency
- Network throughput
- Network latency
- Application dependencies
- Azure Monitor / VM Insights

### 10. VMSS + Load Balancer + Availability

For a highly available scalable web application:

Client
    |
    v
Load Balancer
    |
    +----------------+
    |                |
   VM               VM
    |                |
    +------- VMSS ---+
            |
       Autoscaling

Where stronger infrastructure isolation is required, distribute instances across Availability Zones.
