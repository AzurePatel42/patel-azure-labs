## Key Corrections

### 1. VM Sizing

CPU and RAM capacity come from the selected VM size/SKU.

Adding a managed data disk does not increase:

- vCPU
- RAM

If a VM needs more CPU or RAM, evaluate resizing the VM to an appropriate SKU.

Consider:

- Cost
- SKU availability
- Supported VM family
- Deallocation/downtime requirements
- Application requirements

### 2. Storage vs Compute Capacity

Separate compute capacity from storage capacity.

Compute:

VM Size
    ->
vCPU
    ->
RAM

Storage:

Managed Disks
    ->
OS Disk
    ->
Data Disk

Temporary Disk provides temporary/non-persistent storage.

A disk cannot solve a CPU or RAM shortage.

### 3. Disk Management

When storage capacity is insufficient, consider:

- Expanding an existing managed disk
- Attaching an additional managed data disk

After Azure-side disk expansion, the guest OS may also require partition/filesystem expansion.

Azure disk capacity
    ->
Guest OS
    ->
Partition/filesystem
    ->
Usable capacity

### 4. VMSS Autoscaling

VM Scale Sets are appropriate when multiple VM instances need centralized lifecycle management and automatic scaling.

High workload:

CPU
    ->
Scale Out
    ->
More VM instances

Low workload:

CPU
    ->
Scale In
    ->
Fewer VM instances

Scale out means more instances.

Scale up means a larger VM size.

### 5. Availability Set vs Availability Zone

Availability Sets distribute VM instances across:

- Fault domains
- Update domains

Availability Zones provide stronger physical infrastructure isolation by placing resources in separate zones within an Azure region.

The correct choice depends on the failure domain the architecture must survive.

### 6. Azure Run Command

Azure Run Command can execute commands or scripts inside the guest operating system without relying on inbound RDP or SSH.

Run Command is different from:

- RDP
- SSH

Use RDP/SSH when interactive remote administration is required.

Use Run Command when command/script execution inside the guest OS is the requirement.

### 7. Managed Disks

Managed Disks provide persistent block storage for Azure VM workloads.

Typical storage model:

VM
    ->
OS Managed Disk
    ->
Data Managed Disk
    ->
Temporary Disk

Managed data disks are appropriate for persistent application data.

### 8. Managed Disk vs Snapshot

Managed Disk:

Active persistent block storage.

Snapshot:

Point-in-time copy of disk state.

A snapshot can be used as a source for creating another managed disk.

Snapshot should not automatically be treated as a complete backup strategy.

### 9. Availability vs Disaster Recovery

Availability Set:

Fault-domain and update-domain distribution.

Availability Zone:

Zone-level infrastructure isolation.

Azure Site Recovery:

Regional disaster recovery and failover scenarios.

Always identify the failure domain before selecting the recovery mechanism.
